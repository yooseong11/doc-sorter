# 화면설계서

화면별 캡처와 예외 상황, 그 처리. 캡처는 절마다 찍은 날짜와 릴리스를 적어 둔다.
화면을 만드는 작업이면 해당 화면 절을 먼저 읽는다. 화면을 바꿨으면 캡처도 다시 찍어 바꾼다.

캡처 파일은 `docs/screens/`에 둔다. 파일명은 `화면번호-순번-상태` (예: `s1-02-reading.png`).

원칙: **읽지 못하거나 분류하지 못한 파일도 버리지 않는다.** 미분류로 받아 저장·기록은 똑같이 한다. ([ADR 0007](adr/0007-supported-formats.md))

---

## S1 업로드

파일을 받아 텍스트를 꺼내는 화면. 스토리맵 `받는다`.

### 캡처 (2026-09-18, R1 · 빈 화면은 2026-09-22 R3 화면으로 교체)

sky를 강조색, gray를 바탕으로 쓴다. 색 값은 Tailwind 팔레트에서 가져와 CSS 변수로 둔다([0010](adr/0010-design-tokens.md)).
아래 캡처의 파일 목록은 화면을 확인하려고 넣은 예시 파일이다. 실제 업무 문서가 아니다.

| 상태 | 캡처 | 보이는 것 |
|---|---|---|
| 빈 화면 | ![빈 화면](screens/s1-01-empty.png) | `파일을 선택하면 여기에 목록이 나옵니다.` 파일 선택 버튼 오른쪽에 포트폴리오용 `샘플 데이터로 바로 실행하기` 버튼을 둔다. 드롭존은 R3에서 이 패널 전체에 붙였다 |
| 읽는 중 | ![읽는 중](screens/s1-02-reading.png) | 파일마다 `읽는 중` 스피너 배지. 다 읽을 때까지 분류 시작 버튼은 비활성 |
| 목록 | ![목록](screens/s1-03-list.png) | 다 읽으면 `대기`. `.hwp`는 `읽을 수 없음` 배지와 안내문이 붙지만 목록에서 빠지지 않는다([0007](adr/0007-supported-formats.md)) |
| 분류 중 | ![분류 중](screens/s1-04-classifying.png) | 읽은 파일만 `분류 중`으로 바뀐다. 읽지 못한 파일도 미분류로 처리되어 확인 화면으로 넘어간다 |

상태 배지는 `대기 · 읽는 중 · 분류 중 · 분류됨 · 저장 중 · 저장됨 · 실패`를 한 컴포넌트로 그린다([0013](adr/0013-partial-classify-failure.md)).
S3 저장 진행 표시도 같은 배지를 쓴다([0011](adr/0011-partial-save-failure.md)).

미지원 브라우저 안내는 `showDirectoryPicker`가 있는 브라우저에서 캡처해서 화면에 나오지 않는다([0012](adr/0012-unsupported-browser.md)).

### 실제 로직 (2026-09-18)

- PDF·DOCX는 브라우저에서 실제 텍스트를 추출한다. HWPX는 R2에서 지원하며 현재는 미분류로 넘긴다.
- 앞부분 최대 3,000자만 보관해 분류 요청에 사용한다. 공백 제외 10자 미만이면 읽을 수 없음으로 처리한다.
- 추출 실패는 해당 파일에 실패 상태를 표시하고, 분류 시작 후 S2에서 재시도할 수 있다.
- 분류는 순차 진행하며 처리 중 파일 추가·삭제를 막는다. 읽기 중 삭제한 파일은 늦은 응답으로 복원되지 않는다.
- 분류가 끝나면 성공·실패·미지원 파일을 모두 S2로 넘긴다.
- `샘플 데이터로 바로 실행하기`는 정적 샘플 5개를 fetch한 뒤 `File`로 바꿔 일반 파일 선택과 같은 읽기 경로에 넣는다. 포트폴리오 전용 진입점이다.
- 빈 화면·목록 캡처는 실제 로직으로 갱신했다. 읽는 중·분류 중 캡처는 기존 모양 참고용이다.

### 카테고리 편집 (2026-09-22, R3)

R3에서 고정 카테고리를 편집 가능한 프리셋으로 바꿨다. 프리셋은 분류 요청에 실려 나가므로 **분류 전에만** 고칠 수 있다([0019](adr/0019-categories-in-request-body.md)).
패널은 드롭존(`.upload__panel`) **바깥**에 둔다. 안에 두면 입력칸 위로 파일을 떨어뜨리게 된다.
캡처는 1280×900, 2배 배율. 실제 업무 문서가 아닌 기본 프리셋이다.

| 상태 | 캡처 | 보이는 것 |
|---|---|---|
| 접힘 | ![접힘](screens/s1-05-categories-closed.png) | 한 줄 요약. `카테고리 4개` + 이름을 `·`로 이어 붙인 목록 + 오른쪽 연필 `편집`. 처음에는 접혀 있다 |
| 펼침 | ![펼침](screens/s1-06-categories-open.png) | 맨 위 안내 `설명은 AI가 그대로 읽고 판단합니다.` 행마다 이름·설명 입력칸과 `×` 삭제. 아래에 `+ 카테고리 추가`와 `4 / 8`, 오른쪽 아래 `기본값으로 되돌리기` |
| 막힘 | ![막힘](screens/s1-07-categories-issue.png) | 이름칸이 빈 행. 그 아래 빨간 `이름을 입력해 주세요.`가 붙고, 위 요약 줄의 이름도 `이름 없음`으로 바뀐다 |
| 되돌리기 확인 | ![되돌리기 확인](screens/s1-08-categories-reset.png) | `기본값으로 되돌리기` 자리가 `편집한 카테고리가 모두 사라지고 기본 4개로 돌아갑니다.` + 빨간 `되돌리기` · `취소`로 바뀐다 |

- 이름 20자, 설명 60자에서 입력이 멈춘다. 카테고리는 최대 8개다
- 설명은 비어도 받는다. 거르지 않고 경고만 띄운다([0020](adr/0020-category-hint-unvalidated.md))
- 편집한 프리셋은 브라우저에 저장되어 다시 열어도 남는다([0021](adr/0021-preset-saved-in-browser.md))
- `미분류`는 목록에 없다. 사용자가 지우거나 그 이름을 쓸 수 없다([0014](adr/0014-unclassified-folder.md))
- 실행 취소는 없다. 그래서 `기본값으로 되돌리기`는 누르면 한 번 더 묻는다
- 접힌 요약 줄은 이름을 그대로 이어 붙인다. 이름이 비면 그 자리에 `이름 없음`이 뜬다

## S2 확인

분류 결과를 사람이 확인하고 고치는 화면. 스토리맵 `나눈다` + `확인한다`. ([ADR 0004](adr/0004-confirm-screen.md))

### 구성 (2026-09-18, 껍데기)

S1과 같은 토큰·카드 모양을 쓴다([0010](adr/0010-design-tokens.md)).

| 자리 | 보이는 것 |
|---|---|
| 머리 | 제목 + 안내문. 오른쪽에 `전체` · `확인 필요` 개수 두 칸. 확인 필요가 1개 이상이면 amber로 바뀐다 |
| 묶음 | 카테고리 하나가 카드 하나. 머리에 카테고리명 · 개수 · 카테고리 설명 한 줄([0002](adr/0002-categories.md)). 파일이 없는 카테고리는 그리지 않는다. 미분류 묶음은 맨 위, 테두리 amber |
| 행 | 왼쪽에 펼침 셰브런 · 파일 아이콘 · 파일명 · 크기/형식, 오른쪽에 카테고리 드롭다운 하나만. 바꾸면 그 묶음으로 바로 옮겨간다([0004](adr/0004-confirm-screen.md)) |
| 펼침 | 미분류·분류 실패인 행만 펼친 채로 시작한다. 나머지는 파일명 왼쪽 셰브런이 있는 줄을 눌러 펼친다. 안에는 근거 인용문 또는 실패 사유 + `다시 시도`, 그리고 `미리보기` |
| 바닥 바 | `파일 다시 고르기` · `저장할 폴더 고르기` |

### 실제 연결 (2026-09-18)

- S1의 파일 목록을 App에서 공유하며, 카테고리 수정은 뒤로 갔다 와도 유지한다.
- `다시 시도`는 실패한 파일 하나만 재처리한다. 읽기 실패는 추출부터, API 실패는 분류부터 다시 한다.
- 재시도 중에는 카테고리 수정과 화면 이동을 막는다.
- `저장할 폴더 고르기`는 실제 목록을 S3으로 전달한다. S3 저장 동작은 여전히 데모다.
- `#s2` 데모 진입 대신 S1의 분류 완료 후 이동한다.
- 근거 인용문은 R2이므로 현재 API 응답은 카테고리만 받는다.

## S3 저장

폴더에 넣고 기록표를 남기는 화면. 스토리맵 `저장한다` + `기록한다`.

### 구성 (2026-09-18, R1)

S1·S2와 같은 토큰·카드 모양을 쓴다([0010](adr/0010-design-tokens.md)). 한 화면 안에서 `고르기 → 저장 중 → 결과` 세 단계로 바뀐다.

| 자리 | 보이는 것 |
|---|---|
| 머리 | 제목 + 안내문(`_2` 규칙과 기록표 파일명). 오른쪽에 `전체` 칸, 저장을 시작하면 `저장됨`, 실패가 생기면 `실패` 칸이 붙는다 |
| 폴더 줄 | 고른 최상위 폴더 이름과 `폴더 고르기` · `폴더 바꾸기`. 저장 중에는 잠근다([0003](adr/0003-web-file-system-access.md)) |
| 미리보기 | 저장 전에만 나온다. 만들어질 카테고리 폴더와 개수, 맨 아래 `분류기록표_YYMMDD.csv` 한 줄([0006](adr/0006-log-csv.md)). 미분류 폴더는 amber |
| 목록 | 저장을 시작하면 미리보기 자리에 들어선다. 한 줄에 `원래 파일명 → 카테고리/저장될 이름` + 상태 배지. 위에서부터 한 줄씩 `저장 중 → 저장됨`으로 바뀐다 |
| 바닥 바 | 저장 전 `확인 화면으로` · `저장 시작`(폴더가 없으면 비활성). 끝나면 결과 문구와 `실패분 다시 시도` · `새 파일 분류하기` |

미분류 파일도 최상위에 두지 않고 `미분류` 폴더에 넣는다([0014](adr/0014-unclassified-folder.md)).
상태 배지는 S1과 같은 컴포넌트다. 여기서는 `대기 · 저장 중 · 저장됨 · 실패`를 쓴다([0011](adr/0011-partial-save-failure.md)).

### 실제 로직 (2026-09-18)

- `폴더 고르기`가 `showDirectoryPicker({ mode: 'readwrite' })`를 부르고 핸들을 idb-keyval에 기억한다([0003](adr/0003-web-file-system-access.md)). 다시 열면 권한이 남아 있을 때만 그 폴더를 그대로 쓴다.
- 저장 직전에 대상 폴더를 읽어 저장될 이름을 확정한다. 같은 이름이면 `_2`, `_3` … 을 붙이고 대기 중인 줄에도 그 이름이 보인다([0005](adr/0005-filename-conflict.md)). 폴더는 없을 때만 만들고, 있으면 그대로 쓴다(이름이 정확히 같을 때만 재사용).
- 파일 하나를 쓸 때마다 `분류기록표_YYMMDD.csv`에 한 줄씩 이어 쓴다. 파일을 새로 만들 때만 BOM과 헤더를 붙인다([0006](adr/0006-log-csv.md)).
- 실패해도 반복문은 끝까지 돌고 성공분은 되돌리지 않는다([0011](adr/0011-partial-save-failure.md)). `실패분 다시 시도`와 행의 `다시 시도`는 실패한 파일만 다시 쓴다.
- 기록표에만 실패한 파일은 다시 시도할 때 파일을 다시 쓰지 않고 기록만 남긴다. 같은 파일이 둘 생기지 않게 한다.
- 최상위 폴더 경로는 브라우저가 알려주지 않아 폴더 **이름**만 보여준다.
