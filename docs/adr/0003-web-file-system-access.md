# 0003. 웹 + File System Access API로 폴더 저장

- 상태: 채택
- 날짜: 2026-09-17

## 맥락
분류한 파일을 사용자 PC 폴더에 넣어야 한다.

## 결정
- 웹앱 + 폴더 선택 API(File System Access API)
- 최상위 폴더를 1번 선택하고, 핸들을 IndexedDB(idb-keyval)에 기억
- 카테고리 이름 = 하위 폴더
- 기존에 비슷한 폴더가 있으면 처음에 매핑(폴더명 + 파일명 3개 표시)

## 이유
- 폴더 경로를 환경 변수로 두면 폴더 하나 바꿀 때마다 개발자가 재배포해야 한다. 사용자는 개발자가 아니다.
- Vercel 서버는 회사 내부 파일 서버에 접근할 수 없다. 브라우저가 사용자 PC(연결된 네트워크 드라이브 포함)에 직접 저장하면 이 문제가 사라진다.
- 웹은 배포하는 순간 모든 사용자가 새 버전을 쓴다. 담당자는 설치·업데이트를 하지 않아도 된다.
- 매번 폴더를 고르면 귀찮아서 안 쓴다. 그래서 폴더 핸들을 IndexedDB에 기억한다. 최신 크롬·엣지는 "방문할 때마다 허용"을 제공해 이후엔 선택도 허락도 필요 없다.
- 최상위 폴더 1개 + 하위 폴더 방식은 권한 요청이 1번이다. 브라우저는 보안상 경로 문자열로 직접 접근할 수 없어서, 사용자가 고른 폴더 안쪽만 다루는 이 방식이 제약과 가장 잘 맞는다.
- 카테고리 이름 = 하위 폴더로 두면 경로 입력칸이 없어 잘못 수정할 일이 없고, 카테고리를 추가하면 폴더도 자동으로 따라온다. 폴더 구조는 회사마다 달라서 경로를 미리 고정하지 않는다.
- 기존 폴더 매핑: `근태관리`처럼 비슷한 이름의 폴더가 있으면 `근태` 폴더가 새로 생겨 폴더가 갈라진다. 폴더 이름만으로는 어떤 폴더가 진짜인지 알 수 없고, 파일을 열어보는 건 느리고 남의 인사 서류를 굳이 열게 된다. 파일명 3개면 폴더 용도를 판단하기에 충분하다.

## 버린 대안
- exe(설치형 앱): 보류. exe는 재배포할 때마다 다운로드를 받아야 한다. 자동 업데이트를 붙여도 업데이트 서버, 코드 서명 인증서, 회사 IT 보안 승인이 필요해 1인 개발 부담이 크다. 폴더 한 번 선택하는 편이 설치 + 업데이트 관리보다 가볍다. 회사가 브라우저 사용을 막으면 그때 Tauri·Electron으로 감싼다.
- 관리자 경로 설정: 보류
- 연도 폴더: 보류

## 결과
폴더 선택 API를 지원하는 브라우저에서만 동작한다.
