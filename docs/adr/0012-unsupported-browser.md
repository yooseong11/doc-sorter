# 0012. 폴더 선택 API 미지원 브라우저

- 상태: 채택
- 날짜: 2026-09-18

## 맥락
[0003](0003-web-file-system-access.md)의 결과에 "폴더 선택 API를 지원하는 브라우저에서만 동작한다"고만 적혀 있다. `showDirectoryPicker`는 크로미엄 계열(크롬·엣지)에만 있고, 사파리와 파이어폭스에는 없다. 이 브라우저로 들어온 사용자를 어떻게 할지 정해야 한다.

## 결정
- `'showDirectoryPicker' in window`로 기능이 있는지 확인한다.
- 없으면 첫 화면에서 안내만 하고 진행을 막는다. 업로드 버튼도 비활성으로 둔다.
- 대체 저장 경로(zip 다운로드)는 R1에서 만들지 않는다.

## 이유
- 주 사용자는 회사 경영지원 담당자이고 업무 PC는 대부분 크롬·엣지다([0001](0001-target-user-and-flow.md)). 미지원 브라우저는 예외 경로지 주 경로가 아니다.
- zip을 넣으면 저장 계층이 두 벌이 된다. 폴더 핸들에 쓰는 코드와 zip 트리를 만드는 코드가 따로 생기고, 파일명 충돌([0005](0005-filename-conflict.md))과 기록표 이어 쓰기([0006](0006-log-csv.md))도 각각 구현해야 한다. R1 완료 조건에 없는 일이다.
- 무엇보다 zip은 이 앱이 하는 일을 사용자에게 돌려준다. 압축을 풀고 기존 폴더에 손으로 병합해야 하므로, 기존 폴더를 찾아서 재사용하는 부분([0003](0003-web-file-system-access.md))이 통째로 사라진다. 나눠서 넣어주는 게 이 앱의 전부인데 그걸 다시 사람이 한다.
- 막는 시점을 첫 화면으로 잡은 건, 업로드와 분류까지 되고 저장에서 막히면 AI 호출 비용만 쓰고 끝나기 때문이다. 반쯤 되는 것보다 처음에 안 된다고 말하는 게 낫다.
- 브라우저 이름이 아니라 기능이 있는지로 판단한다. 사파리가 나중에 지원하면 코드를 고치지 않아도 그날부터 열린다. iOS는 크롬도 WebKit이라 이름으로 보면 지원한다고 잘못 읽는다.

## 버린 대안
- zip 다운로드 대체 경로: R3로 보류. 넣게 되면 저장 계층의 인터페이스를 먼저 나눠야 한다.
- User-Agent로 브라우저 이름을 보고 분기: 브라우저가 이름을 바꾸거나 기능을 추가하면 따라가야 한다. 안내 문구에 "크롬이나 엣지로 열어주세요"처럼 이름을 쓰는 건 괜찮지만, 동작을 가르는 조건으로는 쓰지 않는다.
- 안내 없이 두기: 버튼을 눌러야 오류가 나고, 사용자는 원인을 알 수 없다.

## 결과
- 첫 화면(S1)에 미지원 안내 상태가 생긴다. 문구에는 크롬·엣지를 적는다.
- 미지원 브라우저에서는 어떤 화면도 진행되지 않으므로, 분류·저장 쪽에서 이 분기를 다시 볼 일이 없다.
