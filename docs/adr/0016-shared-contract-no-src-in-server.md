# 0016. 공유 계약은 shared/에 두고 브라우저·서버가 각각 어댑터로 붙는다

## 결정
분류 스키마·상수·정규화와 카테고리 목록은 루트 `shared/`에만 두고, `src/`는 브라우저 흐름과 fetch 어댑터, `server/`는 제공자 어댑터를 갖는다. `server/`·`api/`는 `src/`를 import하지 않는다.

## 이유
서버가 브라우저 폴더에서 계약을 꺼내면 의존이 거꾸로 되고 Vite 번들 폴더에 서버가 얽힌다. 검증은 shared의 normalize를 양쪽이 각각 불러 2겹으로 막는다.

## 버린 대안
- `src/lib/`에 계약을 두고 서버가 import: 지금 상태. 브라우저 fetch가 서버 경로에 섞인다.
- `src/shared/`: 서버가 Vite 번들 폴더 안을 계속 들여다봐야 해서 규칙이 흐려진다.
- 서버만 normalize: 서버가 실수하면 화면이 그대로 받는다.
