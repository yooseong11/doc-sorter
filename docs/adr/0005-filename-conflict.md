# 0005. 파일명 유지와 충돌 처리

- 상태: 채택
- 날짜: 2026-09-17

## 결정
- 원래 파일명을 유지한다.
- 같은 이름이 있으면 `_2`, `_3` …을 붙인다.

## 이유
- 처리 날짜를 파일명 앞에 붙이는 방식을 검토했지만, 원래 파일명에 이미 날짜가 있는 경우가 많다(`2026-09-01_연차.pdf`). 날짜가 두 개 적히면 신청일인지 처리일인지 헷갈린다.
- 처리한 날짜는 파일명 밖, 분류 기록표에 남긴다([0006](0006-log-csv.md)). 파일 수정 날짜는 탐색기가 이미 보여준다.
- `getFileHandle(name, { create: true })`는 같은 이름의 기존 파일을 덮어쓴다. 그래서 저장 전에 존재 여부를 확인하고 번호를 붙인다.
- 이렇게 하면 릴리스 1에서 파일명 관련 판단이 거의 없어진다.

## 버린 대안
- AI가 파일명 새로 짓기: 보류. 파일명에 들어갈 사람 이름·날짜·금액은 전부 추출 작업이라, 릴리스 1(분류 + 저장)의 범위가 두 배가 된다. 또 잘못 분류된 파일은 폴더에서 보이지만, 이름이 틀린 파일은 조용히 틀려서 나중에 찾을 수 없다.
