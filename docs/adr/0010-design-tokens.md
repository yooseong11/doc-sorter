# 0010. 전역 디자인 토큰(CSS 변수)

- 상태: 채택
- 날짜: 2026-09-17

## 맥락
화면(확인 화면, 폴더 설정 등)을 만들기 시작하면 색·글꼴·간격 같은 스타일 값이 여러 CSS 파일에 흩어진다. 스타일을 어떤 방식으로 관리할지 정해야 한다.

## 결정
- 전역 디자인 토큰을 만든다.
- 토큰은 CSS 변수(`:root`의 `--이름`)로 한 파일에 모은다. (예: `src/styles/tokens.css`)
- 색·글꼴·간격·모서리·그림자 값은 토큰으로만 정의하고, 컴포넌트 CSS는 `var(--토큰)`으로 가져다 쓴다.
- px 값은 **4px 단위**(4, 8, 12, 16 …)로 정한다.
- `border-radius`는 예외로 **2px 단위**(2, 4, 6, 8 …)까지 허용한다.
- 글자 크기(`font-size`)도 예외로 4px 단위가 아니어도 된다. 단, 짝수만 쓴다(12, 14, 16, 18 …).
- 줄 높이(`line-height`)는 px가 아니라 템플릿처럼 비율로 쓴다. 토큰은 두 개로 둔다.
  - 본문: `145%`
  - 제목: 본문보다 좁은 비율 (예: `120%`)
- **홀수 px 값은 절대 쓰지 않는다.**

## 이유
- Tailwind를 쓰기에는 프로젝트가 작다.
- 그렇다고 CSS를 마음대로 쓰면 같은 값이 여기저기 흩어져서 나중에 수정하기 힘들어진다.
- 토큰 파일 하나만 고치면 화면 전체에 반영된다.
- CSS 변수는 브라우저 기본 기능이라 라이브러리·설정이 필요 없다. ([0009](0009-tech-stack.md)의 가벼운 스택 방향과 맞는다.)

## 버린 대안
- Tailwind: 프로젝트가 작아서 도입 부담에 비해 얻는 것이 적다.
- 토큰 없이 CSS를 자유롭게 작성: 값이 흩어져 나중에 수정하기 힘들다.
- px 단위 규칙을 테스트로 검사(테스트 스크립트, stylelint): 하지 않는다. 컴포넌트 CSS가 토큰만 쓰면 px 값은 토큰 파일 한 곳에만 있어서 눈으로 확인할 수 있다. oxlint는 JS만 검사해서 CSS에는 쓸 수 없다. 필요할 때는 `grep -rnE '[0-9]*[13579]px' src --include=*.css`로 확인한다. 컴포넌트 CSS에 px를 직접 쓰는 일이 반복되면 다시 검토한다.

## 결과
- 컴포넌트 CSS에 색상값(`#fff` 등)을 직접 쓰지 않는다.
- Vite 템플릿의 `letter-spacing: 0.18px`처럼 규칙에 맞지 않는 값도 정리 대상이다.
- Vite 템플릿 기본 CSS(`src/index.css`의 변수, `src/App.css`)는 토큰 파일 기준으로 정리해야 한다.
- CSS·토큰만 바꾸는 커밋은 `style` 타입을 쓴다. (AGENTS.md 커밋 규칙)
